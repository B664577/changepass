# 变更通行证（change-pass）

> 重构最怕的不是改错，是改完没人能证明行为没变 —— 于是宁可不改。
>
> 本工具给一次重构签发一张**可被第三方重算的通行证**：
> 通行证说的不是「我觉得没问题」，而是「在这组输入上，改前改后逐字节相同」。

## 它解决什么

AI 辅助重构的真实瓶颈不在生成，在**验收**。
一段被改写过的代码，评审要回答的问题只有一个：行为变了没有。
今天的回答方式是人读 diff，而人读 diff 既慢又不可复算。

本工具把这个问题变成确定性的：

1. **录**：在改之前，把目标函数在一组输入上的行为录下来（返回值、异常、
   标准输出、以及被声明为可观测的副作用），逐条算哈希；
2. **改**：人或 AI 做重构，本工具不参与；
3. **验**：在改之后重放同一组输入，逐条比对哈希；
4. **签**：全部一致才签发通行证；任何一条不一致，通行证**拒签**，
   并指出是哪一条输入、哪一个字段、差在哪里。

**拒签不是失败，是本工具存在的理由。** 一个从不拒签的通行证等于没有。

## 为什么不是"跑一遍单元测试就行"

单元测试检查的是**我们想到要检查的性质**；
行为等价检查的是**我们没想到的那些**。
一次重构真正的风险在边界：空输入、异常路径、浮点边缘、
顺序依赖、以及那些当初写测试的人没想到的组合。

所以本工具的输入集有三个来源，缺一不可：

- **声明的用例**：维护者手写的，覆盖已知语义；
- **语料采样**：从仓库自身的调用点抽取真实实参；
- **边界生成**：按参数类型自动补空值、极值、异常形状。

三者在通行证上分别计数。**只跑声明用例签出来的通行证会被标记为覆盖不足**。

## 诚实边界

- 行为等价是**在给定输入集上**的等价，不是数学意义上的等价。
  输入集之外的行为，本工具不作任何承诺，通行证上也会写明输入集的来源与规模。
- 不可观测的副作用（写入外部系统、依赖真实时钟与随机数）必须被显式声明并打桩；
  未声明的副作用会让重放不稳定，本工具会检出不稳定并拒绝签发，
  **而不是签发一张不可靠的通行证**。
- 本工具不判断重构是否"更好"，只判断行为是否没变。

## 安装

```bash
python -m pip install -r requirements.txt   # 仅标准库，此文件为空占位
```

需要 Python 3.10 以上。不需要 GPU，不联网。

## 用法

```bash
# 1 录：改之前，录下目标的行为
python -m changepass record --target demo_project/calc.py:normalize --out .cp/base.json

# 2 （人或 AI 做重构，本工具不参与）

# 3 验 + 签：改之后重放并签发
python -m changepass verify --target demo_project/calc.py:normalize --base .cp/base.json
```

退出码：`0` 签发，`3` 拒签（行为不一致），`4` 重放不稳定（有未声明副作用）。

## 跑通内置演示

仓库自带一个 10 行的目标函数与**三次改写**：

```bash
python demo.py
```

| 改写 | 内容 | 预期 |
|---|---|---|
| 一 | 换了写法，求值顺序保持不变 | **签发** |
| 二 | **只把 `hi - lo` 提成变量 `span`** | **拒签** |
| 三 | 看似简化，实则改了两处行为 | **拒签** |

**改写二是本工具最值得被看见的一类命中。** 它只是把一个子表达式提成变量，
没有任何人读 diff 会觉得这里有问题。但原版在 `hi == lo` 时**先返回**，
改版**先算减法** —— 于是 `[None]` 这类输入上，原版返回 `[0.0]`，
改版抛 `TypeError`。

这一条不是设计出来的演示：写这份演示时，作者本以为改写二是等价的，
是工具在边界输入上把它拦下来的。

跑自身测试：

```bash
python -m unittest discover -s tests
```
